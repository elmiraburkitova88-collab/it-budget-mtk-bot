# Заявка IT в бюджет MTK — телеграм-бот

Стек: **Google Apps Script** (бэкенд + логика бота) + **Google Sheets** (каталог/хранилище заявок) +
**Telegram Mini App** (форма заявки — белo-голубой интерфейс с элементами печатных плат/микрочипов).

Файлы:
- `Code.gs` — весь бэкенд: получение сообщений бота (через опрос Telegram,
  см. ниже), диалог выбора отдела, проверка на существующую заявку, приём
  формы, запись в таблицу.
- `Form.html` — форма, которая открывается внутри Telegram как Mini App.
- `index.html` — автономная интерактивная визуализация всего сценария (диалог бота
  + форма), открывается прямо в браузере без Telegram и Google Sheets.
- `PRD.md` — требования к решению, используется как справочник при доработках.

## 1. Разовая настройка

1. **Создайте бота** через [@BotFather](https://t.me/BotFather): `/newbot`, сохраните токен.
2. **Создайте Google-таблицу** (пустую) — она будет базой данных бота.
3. В таблице: `Расширения → Apps Script`. Удалите содержимое `Code.gs` по умолчанию,
   вставьте файл `Code.gs`. Добавьте новый HTML-файл `Form` (имя обязательно `Form`,
   без расширения) и вставьте содержимое `Form.html`.
4. `Настройки проекта → Свойства скрипта` → добавьте свойство `BOT_TOKEN` = токен из BotFather.
5. В редакторе выберите функцию `setup` и нажмите ▶ Выполнить (разрешите доступ). Это создаст
   три листа: **Каталог**, **Заявки**, **Позиции**.
6. Заполните лист **Каталог** реальными позициями вашего IT-каталога (столбец A,
   по одной строке на товар) — сейчас там для примера 3 строки.
7. `Deploy → New deployment → Web app`. Execute as: **Me**, Who has access: **Anyone**.
   Скопируйте появившийся URL (`.../exec`) и сохраните его в свойстве скрипта
   `WEBAPP_URL` — так надёжнее, чем автоопределение адреса.
8. Выберите функцию `startPolling` и выполните ▶ (разрешите доступ) — она создаст
   триггер по времени, который каждую минуту забирает новые сообщения из Telegram.
   **Важно:** боты на Google Apps Script не могут использовать `setWebhook` — веб-приложение
   всегда отвечает редиректом 302 на запрос к `/exec`, а Telegram не следует за
   редиректами при доставке вебхуков. Поэтому вместо webhook бот сам опрашивает
   Telegram через `getUpdates()`.
9. В Telegram напишите боту `/start` — в течение минуты появится список из 7 отделов.

Если позже пересоздадите деплой (новый URL) — обновите свойство `WEBAPP_URL`.

## 2. Как это работает

- Пользователь пишет `/start` → бот показывает **строго фиксированный** список из 7 отделов
  инлайн-кнопками (взять другой отдел или вписать текст невозможно).
- Если у отдела уже есть **активная** заявка на текущий бюджетный год — бот не даёт
  создать вторую, а предлагает открыть и дополнить существующую (это и есть защита от
  «заявки поверх заявки»).
- Иначе бот открывает форму (Mini App) кнопкой «Открыть форму».
- В форме: до 20 разнородных товаров, у каждого — название (со сверкой по каталогу),
  обоснование, количество, единица измерения (по умолчанию «шт.», можно сменить),
  необязательная ссылка. Обязательные поля нельзя оставить пустыми.
- Перед отправкой — блок «Не забыли ли вы про…» с чек-листом типовой периферии
  (мышь, гарнитура, ИБП, картриджи и т.д.); отметка сразу добавляет позицию в заявку.
- По кнопке «Отправить» данные уходят в таблицу, а в чат с ботом приходит подтверждение
  со списком принятых позиций (и что именно отклонено, если что-то не прошло проверку).

## 3. Решения, которые были приняты — проверьте, подходят ли они

Часть требований можно было трактовать по-разному:

- **Минимум 8 символов** применён к полю **«Обоснование»** (это защищает от
  бессмысленных заявок вида «нужно»), а не к названию товара — название чаще всего короче.
- **Проверка по каталогу** сейчас **предупреждает**, но не блокирует отправку: если
  товара нет в каталоге, позиция помечается «⚠ нет в каталоге» и уходит в таблицу с
  пометкой «Есть в каталоге: Нет» — для ручной сверки IT-отделом. Если нужен жёсткий
  запрет отправки при отсутствии в каталоге — это легко поменять в `handleMiniAppSubmit`.
- **Один активный запрос на отдел в год**: пока у отдела есть незакрытая заявка на
  бюджетный год, новые позиции добавляются в неё же, а не в отдельную новую заявку.
  Закрыть заявку (когда бюджет согласован) — вручную сменить статус на «Закрыта» в
  листе «Заявки».
- **Бюджетный год** считается автоматически как «следующий календарный год» и может
  быть переопределён свойством скрипта `BUDGET_YEAR` (например, если цикл согласования
  смещён).
- **Единицы измерения**: шт., компл., уп., пара, м, кг, лицензия, коробка — список
  легко расширить в массиве `UNIT_OPTIONS`.

## 4. Дизайн

Бело-голубая палитра, дорожки и площадки печатной платы в шапке формы, минималистичный
микрочип вместо логотипа, один шрифт (IBM Plex Sans) для текста и моноширинный
(IBM Plex Mono) — только для технических меток вроде номера заявки. Подсказки на
каждом шаге написаны простым языком, без терминов, чтобы форма была понятна и тем,
кто первый раз пользуется такими сервисами.

## 5. Визуализация без развёртывания

Откройте `index.html` в любом браузере — это тот же сценарий (выбор отдела → форма →
подтверждение), но с имитацией Telegram и Google Sheets через `localStorage`, без
необходимости настраивать бота и таблицу.

## 6. Что можно донастроить дальше

- Добавить в лист «Заявки» отдельный статус «Согласована» и уведомление отделу.
- Разрешить IT-отделу выгружать сводный отчёт по всем отделам одной кнопкой.
- Если каталог большой (сотни позиций) — можно заменить `<datalist>` на быстрый
  поиск по подстроке прямо в форме.
