# PRD: «Заявка IT в бюджет MTK»

Телеграм-бот для сбора заявок на офисное IT-оборудование по структурным
подразделениям при формировании бюджета на следующий год.

Документ описывает требования к уже реализованному решению (`Code.gs`,
`Form.html`) — используется как справочник при доработках и передаче задачи
другому исполнителю.

## 1. Проблема и цель

**Проблема.** Заявки на IT-оборудование при формировании годового бюджета
собираются вручную, из-за чего подразделения дублируют заявки, забывают
типовую периферию, а данные приходят в неструктурированном виде (почта,
устные запросы).

**Цель.** Единая точка сбора заявок в Telegram: фиксированный список
подразделений, проверка наименований по IT-каталогу, защита от повторных
заявок по одному подразделению, напоминание о часто забываемом оборудовании,
структурированное хранение в Google Sheets.

## 2. Пользователи

| Роль | Кто | Действия |
|---|---|---|
| Сотрудник подразделения | любой сотрудник одного из 7 отделов | выбирает отдел, заполняет и отправляет заявку через Mini App |
| IT-отдел / бюджетный администратор | владелец Google-таблицы | ведёт каталог, просматривает свод заявок, закрывает заявки после согласования бюджета |

## 3. Границы (Scope)

**Входит:**
- сбор заявок за один бюджетный цикл (год) по 7 фиксированным подразделениям;
- сверка наименований с каталогом, базовая валидация полей;
- предотвращение параллельных заявок от одного подразделения;
- напоминание о типовой забываемой периферии.

**Не входит:**
- согласование и утверждение бюджета (только сбор данных);
- интеграция с ERP/1С/бухгалтерскими системами;
- ролевой доступ/авторизация сложнее идентификации по chat_id;
- редактирование или удаление уже отправленных позиций из интерфейса
  (только через Google Sheets вручную).

## 4. Пользовательский сценарий

1. Пользователь отправляет боту `/start`.
2. Бот приветствует и показывает список подразделений — **строго 7 пунктов
   инлайн-кнопками**, свободный ввод названия отдела невозможен.
3. Бот проверяет, есть ли у выбранного подразделения активная заявка на
   текущий бюджетный год:
   - **Есть** → бот показывает номер заявки, число внесённых позиций, дату
     последнего изменения и предлагает «Дополнить заявку» или «Показать
     список позиций». Создать вторую (параллельную) заявку по этому же
     подразделению нельзя.
   - **Нет** → бот присылает кнопку «Открыть форму», которая открывает
     Telegram Mini App.
4. В форме пользователь заполняет от 1 до 20 разнородных позиций и,
   при необходимости, отмечает пункты из чек-листа «Не забыли ли вы про…».
5. По кнопке «Отправить заявку» форма проверяет поля на клиенте, затем
   отправляет данные на бэкенд.
6. Бэкенд повторно валидирует данные, записывает принятые позиции в таблицу
   и присылает в чат подтверждение со списком принятых и (если есть)
   отклонённых позиций с причиной отклонения.

## 5. Функциональные требования

| № | Требование | Реализация |
|---|---|---|
| FR-1 | Список подразделений фиксирован (7 пунктов), добавить новый или ввести текстом нельзя | инлайн-клавиатура из константы `DEPARTMENTS`, выбор только по `callback_data` |
| FR-2 | Заявка привязана к подразделению и бюджетному году | лист «Заявки», поля «Отдел», «Год бюджета» |
| FR-3 | У подразделения не может быть двух параллельных активных заявок за один год | `findActiveRequest()` проверяет статус ≠ «Закрыта» перед созданием новой |
| FR-4 | До 20 разнородных товаров в одной заявке (совокупно, включая ранее внесённые) | `MAX_ITEMS_PER_REQUEST = 20`, проверка на клиенте и повторно на сервере |
| FR-5 | Поле «Наименование» сверяется с IT-каталогом | автодополнение по каталогу + точное совпадение без учёта регистра; при несовпадении — пометка «нет в каталоге», позиция всё же принимается для ручной проверки |
| FR-6 | Поля «Наименование», «Обоснование», «Количество» обязательны и не могут быть пропущены | `required` на клиенте + повторная проверка в `handleMiniAppSubmit` на сервере |
| FR-7 | Минимальная длина ввода — 8 символов | применено к полю «Обоснование» (`JUSTIFICATION_MIN_LENGTH = 8`) |
| FR-8 | Поле «Ссылка на товар» — необязательное | тип `url`, без `required` |
| FR-9 | Единица измерения по умолчанию «шт.», можно сменить принудительно | `<select>` со списком `UNIT_OPTIONS`, первый пункт выбран по умолчанию |
| FR-10 | Бот задаёт дополнительные вопросы о возможно забытом оборудовании/периферии | блок-чек-лист `FORGOTTEN_CHECKLIST`; отметка пункта добавляет позицию в заявку |
| FR-11 | Пользователь получает подтверждение отправки и список принятых/отклонённых позиций | сообщение от бота после `handleMiniAppSubmit` |
| FR-12 | Заявка формируется на бюджетный год вперёд, а не на текущую закупку | `getBudgetYear()` = текущий год + 1 (переопределяемо свойством `BUDGET_YEAR`) |

## 6. Данные (Google Sheets)

### Лист «Каталог»
| Наименование товара | Категория (необязательно) |

### Лист «Заявки»
| ID заявки | Отдел | Год бюджета | Статус | Создана | Изменена | Кол-во позиций | Chat ID автора |

- ID заявки формируется как `<код отдела>-<год>-<порядковый номер>`, например `D4-2027-001`.
- Статус: «Черновик» → «Черновик (лимит)» при достижении 20 позиций → «Закрыта»
  (проставляется вручную после согласования бюджета).

### Лист «Позиции»
| ID заявки | № | Наименование | Есть в каталоге | Обоснование | Количество | Ед. изм. | Ссылка |

## 7. Требования к интерфейсу (UI/UX)

- Заголовок бота: **«Заявка IT в бюджет MTK»**.
- Палитра: бело-голубая (основной синий `#0b5fa5`, фон `#eaf4fb`, белые карточки).
- Декоративные элементы: дорожки и контактные площадки печатной платы (SVG) в
  шапке формы, значок микрочипа вместо логотипа — единственный акцентный
  визуальный элемент, остальной интерфейс — минималистичные карточки без
  лишнего декора.
- Шрифты: IBM Plex Sans — основной текст; IBM Plex Mono — только для
  технических меток (номер заявки, год).
- Тон текста: дружелюбное приветствие, простые формулировки без терминов —
  форма должна быть понятна пользователю, впервые столкнувшемуся с подобными
  сервисами.
- Форма адаптирована под мобильный экран (Telegram Mini App всегда
  открывается в webview телефона).

## 8. Техническая архитектура

- **Telegram Bot API** — приём команд и callback-кнопок через **опрос (polling)**,
  а не через webhook: триггер по времени (раз в минуту) вызывает `pollUpdates()`,
  которая забирает новые сообщения через `getUpdates()`. Webhook в этой архитектуре
  принципиально не работает — веб-приложение Google Apps Script всегда отвечает
  редиректом HTTP 302 на запрос к `/exec` (браузеры и большинство HTTP-клиентов
  следуют за ним автоматически), а Telegram при доставке вебхуков редиректы не
  проверяет и засчитывает 302 как ошибку доставки.
- **Google Apps Script Web App** — используется только для формы (Mini App):
  - `GET` — отдаёт HTML-форму с подставленными данными: каталог, единицы
    измерения, чек-лист, уже внесённые позиции (при дополнении заявки);
  - `POST` — принимает отправку формы из Mini App (браузер следует за
    редиректом 302 автоматически, поэтому здесь та же особенность не мешает).
- **Хранилище** — Google Sheets, три листа, без внешней базы данных.
- **Передача формы → бэкенд** — `fetch` POST с `Content-Type: text/plain` в
  режиме `no-cors` (чтобы избежать блокировки кросс-доменного запроса);
  подтверждение пользователь получает отдельным сообщением бота в чат, так
  как ответ на `no-cors`-запрос на фронтенде прочитать нельзя.

## 9. Принятые допущения

- Проверка по каталогу — предупреждающая, не блокирующая (можно сделать
  жёсткой, если потребуется).
- Одна активная заявка на подразделение на бюджетный год; дополнительные
  позиции добавляются в неё же.
- Бюджетный год вычисляется автоматически (текущий + 1).
- Список единиц измерения ограничен восемью типовыми вариантами, легко
  расширяется.

## 10. Дальнейшее развитие (вне текущей области)

- Отдельный статус «Согласована» с уведомлением подразделению.
- Сводный отчёт по всем подразделениям одной кнопкой для IT-отдела.
- Быстрый поиск по подстроке в форме, если каталог вырастет до сотен позиций.
